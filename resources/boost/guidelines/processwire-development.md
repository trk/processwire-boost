# ProcessWire Hooks, Page Classes & Modules

- **Hooks (`WireHooks`):** Register in `site/init.php`, `site/ready.php`, or a module's `init()` / `ready()`. Use `addHookBefore` (inspect/mutate `$event->arguments(0)` or set `$event->replace = true` + `$event->return`), `addHookAfter` (inspect/mutate `$event->return`), or URL hooks `$wire->addHook('/api/items/{id}', ...)` (`pw-url-routing`). Prefix hookable methods with `___` (`public function ___methodName()`) and add `@method` PHPDoc on the class.
- **Custom Page Classes (`site/classes/`):** When `$config->usePageClasses = true`, template `blog-post` maps to `site/classes/BlogPostPage.php` (`namespace ProcessWire;`). Activate `pw-custom-page-classes`.
- **Modules (`site/modules/`):** Activate `pw-module-development` (and read its `references/{fieldtype-inputfield,process,textformatter,filevalidator}.md` guide):
  - **Single-Point Namespace Registration:** Register `Vendor\<Module>` -> `__DIR__ . '/src/'` once in the main module's `__construct()` via `$this->wire()->classLoader->addNamespace()` after `parent::__construct()` — never scatter `require_once` or `class_exists` shims.
  - **Lazy `autoload` Boot:** Default to `autoload => false` (or `'template=admin'`). When `autoload => true` is required, defer heavy service/schema initialization until a hook fires.
  - **Signatures, Lifecycle & Typing:** Never narrow parent parameter types, drop optional defaults, or rely on `#pw-internal` methods. Clean up all module tables, permissions, `WireCache`, `pages_meta`, and `site/assets` directories in `___uninstall()`. Provide `API.md` and (for `Fieldtype<BaseName>`) a `<BaseName>Field.php` companion returned from `getFieldClass(array $a = []): string`.
